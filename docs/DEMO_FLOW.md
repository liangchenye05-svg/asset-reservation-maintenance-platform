# 合成环境USER/ADMIN演示

只在自己控制的新演示库准备账号、设备与预约，不连接真实业务库。没有共享默认账号。建议两个USER与一个ADMIN，使用不同窗口或退出后切角色；截图前关闭口令文件与网络头。

1. USER登录，查看设备与个人空列表；另一USER不能读取其预约/工单详情或历史，带正确他人身份应403，不能以匿名401代替。
2. 在可用设备创建未来预约，重叠PENDING允许并存；ADMIN批准一条后，重叠申请不能批准；首尾相接允许。取消仍受归属/状态/开始时间约束。
3. USER报修新单，设备不变，historyComplete=true，历史有真实CREATED。
4. ADMIN受理前查看已批准且尚未结束预约影响，确认保留预约人工协调；受理后PROCESSING、设备MAINTENANCE，真实PROCESSED。
5. USER新的预约申请和ADMIN批准均409；已有批准预约保留。再报修同设备第二单，允许多工单。
6. 完成一单而另一单仍PENDING/PROCESSING，设备不恢复；所有单结束且可靠快照、无暂停时恢复原状态，可用IN_USE演示不固定AVAILABLE。
7. 对明确标记为合成旧数据的样本，新增真实操作后historyComplete仍false，不出现补造的创建/受理事件。
8. 对缺可靠快照的旧处理中设备，ADMIN无说明409；填真实核对说明后只完成工单，设备和暂停保留；兄弟新单也不能解除暂停。不存在解除暂停按钮。
9. 原人工MAINTENANCE且无快照的设备完成后仍维修。完整事件历史但缺设备快照的旧样本也不能猜测恢复。
10. 组合查询/翻页核对total和records，三状态与全部请求正确；390px核对导航/详情/核对框，无整页溢出。

旧数据夹具必须在专用合成库准备并明确标为合成，不能在真实库伪造历史来演示。并发/回滚证据用隔离测试，不在演示或真实库临时加故障触发器。人工验收与自动化分别记录，不虚构签署或能力。
