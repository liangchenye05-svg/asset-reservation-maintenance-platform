# AI辅助开发实践与人工职责

本项目明确使用Codex辅助工程实现，不声称全部代码由开发者独立手写，也不声称开发者已经掌握全部生成代码。

| 环节 | AI实际参与 | 人工确认/验收边界 |
| --- | --- | --- |
| 审计 | 检查源码/API/SQL、未提交差异、隐私与历史 | 用户限定保护范围与每阶段授权 |
| 业务设计 | 提出维修/预约、多工单、历史缺口和快照方案 | 用户明确确认保留预约、受理进入维修、可靠快照及核对后保留现状等政策 |
| 工程实现 | 辅助查询DTO/SQL、历史、事务/锁、迁移、前端、隔离测试及文档 | 具体技术实现不是用户逐行指定；能力需通过源码解释和复现检验 |
| 自动验证 | JUnit、真实HTTP、锁等待、故障回滚、浏览器布局、差异和数据一致性 | 自动化不等于人工已操作所有用例 |
| 人工操作 | 提供合成环境、清单和证据说明 | 用户已报告亲自操作独立B2环境未发现明显问题，并接受最终阶段B验收；未补造逐条签署记录 |
| 交付 | 白名单同步、匿名隐私检查及公开说明 | 用户保留提交/发布决定；本轮不commit、push或公开 |

曾定位浏览器异步等待脚本问题和完整历史但缺快照的遗漏，保留失败与后续修正证据，没有放松业务断言。启动阶段曾漏核JWT环境继承，按规则停下；后续从合法IDE运行配置复用原密钥完成只读验收，未擅自换密钥。这些经历说明需要核验AI建议，不把BUILD SUCCESS当全部功能正确。

求职可描述：使用AI辅助代码阅读、业务方案比较、实现和测试，通过真实接口、事务数据及差异审查验证结果。用户已确认业务规则和进行操作验收；对事务、锁、SQL和权限的独立讲解能力尚未形成完整逐项验收，不据此宣称全部掌握。

建议亲自说明Controller→Service→Mapper职责、设备锁为何要与条件UPDATE同时存在、历史为何同事务、为何完成不代表设备可恢复；实际能解释多少写多少。没有测量节省工时、性能提升百分比、QPS或线上使用规模，不编造指标。

公开只发布源码/合成用例及证据摘要，不发布聊天、私人身份、原始日志、JWT、备份或真实数据库材料。最新匿名复验与既有主项目证据分别见[TESTING](TESTING.md)。
